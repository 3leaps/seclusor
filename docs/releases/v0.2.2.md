# Release Notes — v0.2.2

**Release Date**: August 17, 2026

**Status**: Input safety, operator guidance, and dependency maintenance

## Overview

Seclusor v0.2.2 is a compatibility-focused patch for interactive secret entry,
passphrase handling, encrypted-write guidance, and internal dependency hygiene.

Terminal use of `secrets set --value-stdin` is now hidden by default and closes
on Enter. Piped and redirected input keeps its existing byte-stream behavior.
Line-oriented passphrase channels now handle LF and CRLF consistently, while
the environment channel deliberately retains exact-byte behavior for narrow
legacy recovery.

The release also extends self-lockout advisories to identity-bearing encrypted
`set` and `import-env` writes and updates the private signing, digest, entropy,
error, and embedded-document build dependencies without changing public data
formats.

## Who this is for

- **Operators** entering secret values interactively with
  `secrets set --value-stdin`
- **Automation owners** sharing passphrase files or stdin input across Unix and
  Windows environments
- **Teams** writing encrypted documents with identities that may not belong to
  the configured target recipient set
- **Integrators** who need signing-envelope and library API compatibility across
  a dependency refresh

## Highlights

### Hidden-by-default interactive value entry

When stdin is a terminal, `secrets set --value-stdin` now displays a `Value:`
prompt, disables echo, reads a bounded value, and accepts Enter. Terminal state
is restored after successful input, errors, interrupts, and unwinding.

Use `--echo-value` only when visible terminal entry is intentional. The switch
requires `--value-stdin` with terminal stdin. In that explicit visible mode,
input retains the existing EOF terminator. Piped or redirected stdin is
unchanged and rejects `--echo-value`.

This controls input visibility. It is separate from `secrets get --reveal`,
which controls whether a stored value is printed.

### Consistent line-oriented passphrases

Interactive, file, and stdin passphrase channels remove one trailing LF or CRLF
line ending and reject a value that is empty after normalization. This makes
passphrase files created on Unix and Windows behave consistently.

Environment passphrases remain byte-for-byte unchanged. That exception permits
recovery of an identity created from a legacy CRLF-terminated passphrase file:
provide the exact value through `--passphrase-env`, create a replacement
identity with normalized file or stdin input, rekey encrypted data, retire the
legacy identity, and unset the variable.

### Encrypted-write self-lockout advisory

Encrypted `set` and `import-env` operations now emit the same advisory used by
`rekey` when none of the identities already loaded for the operation belongs to
the target recipient set. The notice does not load extra identities and is not
a decryption guarantee. Recipient-set validation still runs independently and
continues to fail closed where required.

Verify the resulting document with an identity for the target set before
retiring an old identity.

### Dependency and build maintenance

- Updated the private Ed25519, SHA-256, and entropy dependencies behind the
  existing signing wrappers
- Added byte-exact compatibility coverage for signing vectors and versioned
  envelope fixtures
- Updated first-party error derives
- Replaced the embedded-docs YAML build manifest with JSON and removed the
  build-only YAML parser

The signing envelope version, canonical bytes, public signing APIs, and
verification behavior are unchanged.

## Upgrade notes

1. Install v0.2.2 from the GitHub release, Homebrew tap, or Scoop bucket.
2. Interactive `secrets set --value-stdin` users should press Enter to finish
   hidden input. Add `--echo-value` only when visible terminal entry and the
   existing EOF terminator are deliberate.
3. Scripts that pipe or redirect value input do not need changes.
4. Keep using file or stdin passphrase channels for ordinary automation. Use
   the exact-byte environment channel only for workflows that require it,
   including the narrow legacy CRLF recovery path.
5. Treat a self-lockout warning as a cue to verify decryptability with the
   target identity, not as proof that the write is unsafe or safe.

## Compatibility

- Document schema and ciphertext formats are unchanged.
- Rust, Go, TypeScript, and C-ABI public API contracts are unchanged.
- Existing signing envelopes remain byte-compatible with the updated signing
  and digest dependencies.
- Piped and redirected `--value-stdin` behavior is unchanged.
- **Intentional terminal behavior change:** interactive `--value-stdin` is
  hidden by default and ends on Enter. Explicit `--echo-value` retains visible
  input and the existing EOF terminator.
- Environment passphrases remain exact-byte inputs; interactive, file, and stdin
  passphrases now normalize one trailing LF or CRLF.

## Security and operational notes

The `secrets run` child-environment issue was fixed in v0.2.1. See
[GHSA-2w88-3q86-736g](https://github.com/3leaps/seclusor/security/advisories/GHSA-2w88-3q86-736g)
for affected versions, severity, and current CVE status. Install v0.2.2 for the
additional input and operator-safety improvements in this release.

Residuals to keep in mind:

- `--echo-value` deliberately exposes terminal input and retains the existing
  EOF terminator; hidden terminal input is the default.
- A self-lockout warning is advisory. Verify decryptability after a recipient
  change and before retiring old identities.
- `--passphrase-env` remains present in the parent process environment for that
  invocation. Prefer file or stdin channels for ordinary use.
- This release does not add identity rotation automation or a general clean
  child-environment mode.
