# Release Notes — v0.2.3

**Release Date**: November 14, 2026

**Status**: Encrypted pack sealing, clean child environments, macOS ACL guards, and signed release provenance

## Overview

Seclusor v0.2.3 is a hardening and release-provenance update. It closes a silent
plaintext write trap when recipient flags are supplied against an unencrypted
document, adds `secrets run --clean-env` to scrub ambient parent environment
variables before launching a child process, clears and verifies macOS extended
ACLs on private files, and establishes OpenPGP-signed dual release tags and
`decernor` fingerprint anchors for release verification.

Document formats, ciphertext, and Rust, Go, TypeScript, and C-ABI contracts are
unchanged.

## Who this is for

- **Operators and automation owners** creating or updating encrypted documents
  with `secrets init`, `secrets set`, `secrets import-env`, or
  `secrets inline encrypt`
- **Teams running child commands** under `secrets run` who want ambient parent
  environment variables scrubbed via `--clean-env` and explicit `--env-allow`
- **macOS users** storing age identities, Ed25519 signing keys, or decrypted
  outputs in directories that may carry inherited extended ACLs
- **Go 1.27+ consumers and release verifiers** who rely on prebuilt CGo FFI
  archives and cryptographically signed release tags and manifests

## Highlights

### Pack-sealing guards and inline encryption ergonomics

Previously, running `secrets set` with `--recipient-file` against a plaintext
document created via `secrets init` without `--codec bundle` ignored the
recipient flag and wrote the credential value in plaintext.

In v0.2.3:

- `secrets set`, `secrets unset`, and `secrets import-env` **fail closed**
  without modifying the target file whenever `--recipient`,
  `--recipient-file`, `--recipient-env-var`, or `--allow-recipient-mismatch` is
  supplied against an unencrypted plaintext document.
- `secrets init --codec inline` creates an empty inline-encrypted skeleton on an
  absent target path with established schema `v1.1.0` `recipients` metadata, so
  subsequent `secrets set` and `secrets import-env` writes encrypt values in
  place without a plaintext intermediate file.
- `secrets inline encrypt` accepts `-` on `--input` and `--output` for streaming
  without writing plaintext to disk.
- `--recipient-file` is now repeatable across recipient-taking commands
  (`init`, `set`, `import-env`, `rekey`, `bundle encrypt`, `inline encrypt`, and
  `blob encrypt`), deduplicating recipients in first-seen order within the
  configured recipient-count bound.
- Interactive passphrase and echoed value prompts on Unix require a foreground
  controlling terminal and fail fast in non-interactive runners instead of
  hanging.

### Clean child environments for `secrets run`

`secrets run` adds `--clean-env` and repeatable `--env-allow <VAR>`:

- `--clean-env` clears inherited parent environment variables down to a minimal
  platform baseline (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `LANG`,
  `LC_ALL`, `LC_CTYPE`, `TMPDIR`, and `TZ` on Unix; `SystemRoot`, `SystemDrive`,
  `WINDIR`, `COMSPEC`, `PATHEXT`, `PATH`, `TEMP`, `TMP`, `USERPROFILE`,
  `APPDATA`, `LOCALAPPDATA`, `HOMEDRIVE`, `HOMEPATH`, and `USERNAME` on Windows)
  before overlaying decrypted project credentials. Any other ambient variable
  requires an explicit `--env-allow <VAR>`.
- `--env-allow <VAR>` passes named variables through from the ambient
  environment when `--clean-env` is active (or alongside default inheritance).
- The v0.2.1 `--passphrase-env` exclusion and passphrase-value equality checks
  still hold unconditionally, even if the variable name is listed in
  `--env-allow`.
- When `--passphrase-stdin` unlocks a protected identity for `secrets run`, the
  child process `stdin` is rebound to null so the consumed stdin stream is not
  inherited by the child.

### macOS extended-ACL protection on private files

On macOS, extended ACL entries can grant read or write permissions independently
of POSIX `0600` mode bits:

- **Create / write:** before writing private bytes (age identity files, Ed25519
  signing keys, and decrypted plaintext outputs), seclusor rejects parent
  directories whose ACL grants non-owner write, `add_file`, or `delete_child`
  access, creates the file with `0600` (`O_NOFOLLOW`, single hardlink check),
  clears any inherited extended ACL on the file descriptor, and verifies that no
  non-owner ACL entries remain.
- **Load:** `assert_secure_permissions` rejects parent directories with unsafe
  writable ACLs, fails closed if file ACL inspection fails, and emits a warning
  on `stderr` when an existing private file carries a non-owner extended ACL
  grant:
  ```bash
  ls -le ~/.config/seclusor/identity.txt
  chmod -N ~/.config/seclusor/identity.txt
  ```
- **Platform scope:** extended-ACL inspection and clearing run on **macOS
  only**. **Linux** remains mode-only by design (`0600` sets the POSIX ACL
  group/mask bits to zero so named ACL entries grant no access). **Windows** is
  not covered by POSIX mode or macOS ACL preflight; protect identity and output
  paths with NTFS ACLs or user-only directories.

## Compatibility

- Document schema (`v1.0.0` and `v1.1.0`) and age ciphertext formats are
  unchanged.
- Rust, Go, TypeScript, and C-ABI public API contracts are unchanged.
- **Intentional fail-closed CLI changes:**
  - `secrets set`, `secrets unset`, and `secrets import-env` reject
    `--recipient`, `--recipient-file`, `--recipient-env-var`, and
    `--allow-recipient-mismatch` when the target document is unencrypted
    plaintext.
  - Unix interactive passphrase and echoed value prompts fail fast when no
    controlling terminal is present.
  - Plaintext file outputs enforce `0600` permissions on Unix and reject
    symlinks or multiple hard links.
- Existing private files on macOS with a non-owner extended ACL emit a warning
  on load (`ls -le` / `chmod -N`); newly created private files clear inherited
  ACLs before writing and refuse parent directories with non-owner write/replace
  ACLs.

## Security and operational notes

- **Historical plaintext write condition (`v0.2.0` – `v0.2.2`):** if an operator
  ran `secrets init` without `--codec bundle` and then ran `secrets set` with
  `--recipient-file` (or `--recipient`), earlier versions ignored the recipient
  flag and wrote the value in plaintext. Audit any repository secrets file
  initialized that way; if plaintext values were committed or shared, convert or
  re-initialize the file with `--codec bundle` or `--codec inline` and rotate
  the affected credentials.
- **macOS ACL scope:** extended-ACL clearing and load warnings apply on macOS
  only. Linux relies on `0600` POSIX mode enforcement; Windows does not run
  POSIX or macOS ACL preflights.
- **`secrets run` passphrase channels:** prefer `--passphrase-file` or
  `--passphrase-stdin`. Even with `--clean-env`, a passphrase supplied via
  `--passphrase-env` remains in the parent `seclusor` process environment for
  the lifetime of that invocation. The earlier `secrets run` child-environment
  advisory remains documented in
  [GHSA-2w88-3q86-736g](https://github.com/3leaps/seclusor/security/advisories/GHSA-2w88-3q86-736g).
